# Raptor Telegram News Bot — v5.3

این نسخه بر پایه فایل‌های v5 ارائه‌شده ساخته شده و state قبلی را با مهاجرت افزایشی حفظ می‌کند. Python 3.10+ توصیه می‌شود.

## استقرار در Railway

فایل‌های این بسته را در مخزن GitHub جایگزین کن. Start Command برابر `python bot.py` باشد یا از Procfile فعلی پروژه استفاده کن. برای ماندگاری صف و تاریخچه، Volume را روی `/data` متصل کن و `STATE_FILE=/data/state.json` قرار بده. فقط یک replica/worker اجرا شود؛ چند نمونه هم‌زمان می‌توانند با polling تلگرام رقابت کنند.

متغیرهای ضروری:

```env
BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
OWNER_TELEGRAM_ID=YOUR_NUMERIC_TELEGRAM_USER_ID
TARGET_CHAT_ID=@khaatshekaan
SOURCE_CHANNELS=MaxOsintIntel,OSINTWarfare,defenseexpress_ua,WarPeaceAndYou,RazmAvaran_org
GROQ_API_KEYS=YOUR_GROQ_KEY
GROQ_MODEL=openai/gpt-oss-120b
GEMINI_API_KEYS=YOUR_GEMINI_KEYS_COMMA_SEPARATED
GEMINI_MODEL=gemini-3.8-flash
MISTRAL_API_KEYS=YOUR_MISTRAL_KEY
MISTRAL_MODEL=mistral-small-latest
POLL_INTERVAL_SECONDS=180
STATE_FILE=/data/state.json
TEST_MODE=false
AI_CLASSIFIER_ENABLED=true
AI_CLASSIFIER_MODEL=llama-3.1-8b-instant
```

کلیدها را در README، GitHub یا گفت‌وگوها قرار نده. اگر کلیدی قبلاً افشا شده، آن را rotate/revoke کن. نام مدل‌ها ممکن است با تغییرات ارائه‌دهنده نیاز به به‌روزرسانی داشته باشند.

## تغییرات v5.3

- **هماهنگی state:** یک `RLock` مشترک، چرخه اصلی و پردازش رویدادهای پنل را سریالی می‌کند؛ ذخیره فایل همچنان اتمی است.
- **ثبت وضعیت ارسال:** پیش از ارسال، `delivery_status=sending` ثبت می‌شود. خطای مبهم یا restart در وضعیت sending به `needs_review` می‌رود تا خبر کورکورانه دوباره ارسال نشود. مدیر می‌تواند پس از بررسی کانال «بازگردانی به صف» را بزند. Bot API کلید idempotency برای ارسال پیام ندارد، بنابراین جلوگیری مطلق از تکرار در تمام حالت‌های شبکه ممکن نیست.
- **رد تحریریه‌ای نهایی:** خبرهایی که به‌دلیل امتیاز زیر حداقل رد می‌شوند، به‌عنوان تصمیم تحریریه ثبت می‌شوند و نباید فقط به همین دلیل retry فنی شوند.
- **تیتر بولد:** تیتر در پیام‌های متنی و کپشن رسانه با HTML امن و بولد ارسال می‌شود.
- **ویرایش خبر صف:** ویرایش مستقیم متن، عکس/رسانه، بازنویسی با سبک کوتاه‌تر/رسمی‌تر/زمینه بیشتر، مشاهده متن کامل و منابع، انتشار فوری، زمان‌بندی دقیقه‌ای یا زمان دقیق تهران.
- **کنترل صف:** بالا بردن/پایین بردن، پین‌کردن یک خبر برای انتشار بعدی، و بازگرداندن خبر قرنطینه‌شده به صف.
- **هشدار مالک:** همه ارائه‌دهنده‌های AI در cooldown، خطای تکراری یک منبع، نبود انتشار بیش از چهار ساعت، صف بزرگ و نزدیک‌شدن به سقف روزانه. هشدارها دارای cooldown هستند تا اسپم نشوند.
- **جمع‌بندی هفتگی:** خلاصه تعداد پست‌ها بر اساس ارائه‌دهنده AI، منبع و bucket به مالک ارسال می‌شود.
- **طبقه‌بند اولیه ارزان:** طبقه‌بند دسته‌ای با مدل کوچک Groq (`llama-3.1-8b-instant`) و fail-open؛ اگر مدل یا پاسخ در دسترس نباشد، پست‌ها به مسیر اصلی می‌روند. کاهش توکن تضمین‌شده نیست و به نسبت پست‌های ردشده/اندازه متن بستگی دارد؛ متغیر `AI_CLASSIFIER_ENABLED=false` آن را خاموش می‌کند.
- **مدیریت منابع:** منبع را موقتاً غیرفعال یا فعال کن بدون حذف از تاریخچه؛ شمارنده‌های دریافت/انتشار/خطا نگهداری می‌شوند.
- **اولویت‌ها و سکوت موضوعی:** واژه‌های مسدودشده، واژه‌های اولویت‌دار و سکوت موقت برای موضوع مشخص قابل تنظیم‌اند.
- **پروفایل انتشار:** حالت عادی از برنامه موجود پیروی می‌کند؛ حالت جنگ فاصله را به ۱۰ دقیقه می‌رساند و ساعت سکوت را دور می‌زند. با احتیاط فعالش کن.
- **توقف زمان‌دار:** یک ساعت، تا ساعت ۸ صبح تهران یا تا خبر مهم بعدی؛ ادامه دستی هم موجود است.
- **تاریخچه:** جستجوی متنی، خروجی CSV و `/find <message_id>` برای یافتن رکورد و AI سازنده.

## نکات و محدودیت‌های مهم

- **بازدید واقعی پست‌ها:** این نسخه بازدیدها را به‌عنوان داده قطعی گزارش نمی‌کند؛ Telegram Bot API در این جریان، شمارش تاریخی/پایدار بازدید برای همه پست‌ها را تضمین نمی‌کند. برای تحلیل واقعی بازدیدها معمولاً باید منبع داده مجاز دیگری مانند MTProto/Telethon با نشست کاربر و تنظیمات جداگانه اضافه شود. جمع‌بندی هفتگی فعلی تعداد پست‌ها و منابع است، نه رتبه‌بندی بازدیدها.
- **قوانین تأیید خودکار چندشرطی AND/OR:** در این بسته موتور قوانین چندشرطی و انتشار مستقیم بدون صف پیاده‌سازی نشده است؛ این مورد به تعریف دقیق قواعد، لاگ ممیزی و تست‌های جداگانه نیاز دارد تا خبر ناخواسته مستقیماً منتشر نشود.
- **فیلتر تاریخ/منبع/bucket در تاریخچه:** جستجوی متنی و CSV فراهم شده؛ فیلترهای ترکیبی تاریخ/منبع/bucket در این نسخه کامل نیستند.
- **تنوع دکمه‌های ویرایش:** تیتر و متن به‌صورت مستقیم قابل ویرایش‌اند و بازنویسی سبک‌محور موجود است؛ ابزار اختصاصی برای تغییر لحن دلخواه، بررسی مستقل اعتبار و ویرایش تمام metadataها هنوز کامل نیست.
- **گزارش منبع:** شمارنده‌ها از زمان فعال‌شدن v5.3 به بعد تکمیل می‌شوند؛ برای تاریخچه قدیمی‌تر ممکن است منبع/AI ثبت نشده باشد.
- **قفل مشترک:** برای سازگاری وضعیت، پنل هنگام پردازش طولانی شبکه/AI ممکن است چند لحظه منتظر بماند. در نسخه‌ای با ترافیک بالا، معماری command queue تک‌رشته‌ای از قفل سراسری بهتر است.

## راه‌اندازی امن

1. ابتدا `TEST_MODE=true` بگذار و صف/پنل را بررسی کن.
2. مطمئن شو `OWNER_TELEGRAM_ID` شناسه عددی حساب مالک است.
3. دسترسی ربات به کانال مقصد را بررسی کن.
4. پس از تأیید، `TEST_MODE=false` بگذار و یک worker نگه دار.
5. در صورت مشاهده `needs_review`، قبل از بازگرداندن خبر به صف، کانال را از نظر انتشار قبلی بررسی کن.
